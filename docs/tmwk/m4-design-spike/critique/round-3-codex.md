# Round 3 — Codex critique

Inspected all eight listed image pairs, dark and light, against VISION, round 2, the recommendation, STYLEGUIDE and the real composer/menu. Keep Finalist 1 and the bottom Chat dock. Both themes support the direction; neither fixes the behavioral gaps.

## Top fixes

1. Replace the pointless clarification with a genuinely missing decision.
2. Preserve attention reasons and access when density, filters or grouping change.
3. Move status reordering out of a cascading submenu; stop treating ongoing as a status.

## New ticket — right direction, unfinished contract

**Right:** “What should get done?” dominates; branch naming disappears; Project inherits the filter; Auto and the user's default agent remove routine decisions. Project/Run on, optional source, Agent/settings, Advanced and Create more retain recognizable composer anatomy. The empty primary action is correctly disabled.

**Fix, in priority order:**

1. In `new-ticket-clarify`, the request already names sidebar and PR reviewers. Asking “which avatars?” because the issue mentions less makes the partner look unable to read, and elevates outside context over explicit direction. Use an actually unresolved tradeoff, offer a recommendation, and retain free-text answers. Link the question to this ticket; show submitted, delivered and failed-answer states.
2. The event **does read as an event**: timestamped divider, ticket glyph, structured request and no user bubble. The matching title in Quiet plus Open ticket make the hand-off legible. But the acknowledgement repeats the delegation line and adds host scheduling trivia. Keep a short plan acknowledgement; put actual owner/host in the retained delegation event. Show “Preparing brief” before launch confirmation; “Delegated” and “owns it” need confirmed state. Keep submitted Auto as historical intent, distinct from actual placement.
3. **Keep Create more**, as requested, but define its tension with opening Chat: open Chat on submit, then reopen the cleared sheet over it with Project retained; switch it off to finish. **Cut explicit Save as draft for v1** until drafts have a visible home and resume path. Preserve unfinished input on dismissal instead.
4. The real source field is a searchable picker, not merely a URL input. Preserve source selection/clear, project acquisition and host connection/setup recovery. “Create from” needs to distinguish branch context from permission to reuse/write that branch. Remove unexplained Advanced if it contains nothing useful after naming is dropped. Replace the helper with “Opens Chat to brief and delegate this request.” Make absent/multiple project selection valid if description truly is the only requirement.

## Ticket options — keep capability behind disclosure

**Right:** Show/group/arrange/filter sections and trailing values follow the real menu. Replacing card styles and worktree filters with ticket concepts is sound. Attention stays default.

**Fix, in priority order:**

1. Project one-line mode removes every question/blocker; Host metadata truncates titles and even the stop reason. Always preserve attention reasons, irrespective of the Reason checkbox or density. Treat one-line as a quiet-row preference; metadata loses space first. Restore consistent session disclosure in grouped examples.
2. Hide ongoing must not hide an ongoing decision. The pinned Needs you entry must remain actionable, independent of row filters and collapsed groups, with explicit scope when project/host filters exclude needs. Preserve the old active-filter badge and add Clear filters/filtered-empty recovery.
3. Agent and Age are optional inspection power; keep off by default. Label Age “Created” or “Last activity.” Group by None should say “Sort by.” Remove the worktree-filter migration paragraph from the permanent menu; provide a real worktree-view route instead. Existing users may miss PR grouping and manual Project order: retain those in the worktree view, and consider Project order only when grouping tickets by Project. Do not silently discard those preferences.

## Status order — good guardrail, wrong editor

**Right:** pinned count, distinct decision/stop/result shapes, per-user order and Reset to default. Done-first is a legitimate preference.

**Fix, in priority order:**

1. Ongoing is a kind, not a state: a watcher can be working, waiting, paused or awaiting a decision. Remove the exclusive Ongoing status bucket; retain its repeat marker.
2. Use “Status order…” to open a small stable popover with drag handles, keyboard Move up/down and Reset. Cascading menus are fragile drag targets and poor on touch. Keep the pinned-count explanation outside the sortable list.
3. The count is visibly above Done; scroll pinning and decision delivery to Chat remain unproven. Test both, including hidden ongoing work. The earlier “Three things” answer in clarification now needs a timestamp or subsequent-change marker.

No retired “Main chat” or “Across all projects” copy returned. “SSH · idle” and the acknowledgement's idle-based choice imply deferred load awareness; use verified availability/checkout facts instead. Keyboard focus, multiline Enter versus platform submit chord, Esc, narrow layouts and remote failures still need interaction validation.
