# Round 2 — Codex critique

**Rank: 1, 2, 3. Ship Finalist 1’s structure with the conversation-and-rail ticket view.** I inspected every listed finalist and reference PNG in both themes. The power is now behind disclosure; the reasons finally outrank the machinery. Neither theme changes the verdict.

## Ranking

1. **Attention list.** Best M4 default: decisions, stops and results remain visible while I converse or inspect another ticket; sessions sit beneath tickets. The fixed Chat dock is a clear return home, though its bottom placement undersells the main conversation. This most directly delivers “the power of Orca and the simplicity of grokbot/dots.”
2. **Chat on top.** A close second, and a better statement of the vision’s conversational center. Tickets now read as tickets rather than alternative chats. But Chat, Search, divider and section headings push useful work down; Projects adds a second navigation system. I would move it first if laptop-sized interaction checks show faster return to Chat without materially hiding quiet work, and Projects demonstrably preserves necessary workspace access.
3. **Shelf and queue.** Stable navigation is valuable, but this version purchases it by hiding reasons in the sidebar and bolting an action dashboard onto the composer. Six needs already become four rows plus “2 more”; the queue competes with conversation and disappears when inspecting another ticket. Session disclosure is absent. It could win with persistent attention access outside Chat, explicit session access, and a compact queue that preserves conversation space at narrow sizes.

## Winner: remaining flaws, in order

1. **Contradictory truth.** `f1-chat-open` says “Nothing needs you” beside three outstanding needs. Derive both surfaces from the same current records; timestamp historical answers and visibly identify subsequent changes. This destroys trust faster than any layout defect.
2. **State labels overclaim.** “Running 4” contains unreachable tickets and ongoing watchers that may be waiting. Use “Quiet” or “Other active tickets”; preserve working/waiting/paused/disconnected distinctions inside. In busy, “PR #420 ready · 1 open question” belongs at decision priority if that question needs me; otherwise say whose question it is.
3. **Reasons still truncate.** The deployment row loses its error rate; the host-loss explanation is cut off. Allow two reason lines, and expose full titles/reasons through keyboard focus and opening. Never make hover the only route.
4. **Disclosure is inconsistent.** Most collapsed rows have no visible chevron; the busy migration row has one. Show the same separate disclosure target for every ticket with sessions, including on touch and keyboard focus. Selection must not expand automatically. Preserve selection and scroll position when priority changes.
5. **Cross-project identity is missing.** Duplicate titles are indistinguishable under All projects. Add project/workspace context when needed; keep folder workspaces reachable without inventing a repository. Finalist 1’s replacement for existing workspace navigation remains unshown.
6. **Color still does semantic work.** Stop and result are identical dots apart from hue. Use distinct status shapes with accessible names. Keep reason text readable in both themes; the light-theme yellow waiting marks are particularly weak.
7. **Competing entry points.** Explain the plus as “New ticket,” route it through conversational delegation, and make the empty-state Chat reference actionable. Remove the redundant “Needs you 0” line.

## Ticket view

The rail hybrid wins: owner conversation for direction, retained events for accountability, Code/Where/Sessions for inspection. The page makes work feel like a report; pure conversation crowds sessions into the header. Keep Watch all as an explicit deeper view with direct input and an obvious return.

The hybrid still repeats sessions in two places and host/model metadata in the header and rail. Collapse the sidebar subtree by default on ticket opening; simplify the header. Keep pending decisions reachable after long histories, show goal and instructions on demand, and provide evidence beside result acceptance. On narrow/mobile layouts, fold the rail into a disclosure without losing session access.

## States and copy

Busy is credible only with demonstrated scrolling and keyboard access; PNGs prove neither. Unreachable correctly retains questions, but attention rows need an accessible last-report timestamp too. Missing: stopped/suspended environment versus permanently lost host, laptop sleep, reconnecting, paused work, failed answer delivery, filtered-empty results, and acceptance pending acknowledgment.

“Host lost: the Ona environment stopped” conflates two explicitly different vision states. Finalist 3’s “Retry on MBP” promises deferred recovery/migration; remove it or explicitly offer a new delegation with possible lost work. “The owner sees it” requires actual history delivery, including after disconnection. “Main chat” and “Across all projects” have not returned; “Fix flaky checks detail link” unfortunately survives everywhere and still looks like leaked implementation copy.
